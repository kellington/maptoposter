What It Does

A tool to generate minimalist, print-quality city map posters. Give it a city and country, it fetches OpenStreetMap road/water/parks data via OSMnx, renders it with matplotlib using a chosen colour theme, and saves a PNG. Supports 17 built-in themes, multilingual city labels (Japanese, Arabic, Thai, Korean, and more), custom coordinates, and configurable size/resolution. The poster output goes to posters/ named {city}_{theme}_{timestamp}.png.

How to Generate a Poster

The most useful section — copy, paste, edit the city/theme, run.

Single poster (default terracotta theme)
uv run ./create_map_poster.py --city "Edmonton" --country "Canada"
With a specific theme
uv run ./create_map_poster.py --city "Paris" --country "France" --theme noir --distance 10000
All 17 themes at once (for comparison)
uv run ./create_map_poster.py --city "Tokyo" --country "Japan" --all-themes
List available themes
uv run ./create_map_poster.py --list-themes
Custom size (A4 print — 2480 × 3508 px @ 300 DPI)
uv run ./create_map_poster.py --city "Venice" --country "Italy" --theme blueprint -W 8.3 -H 11.7
Ambiguous location — override coordinates
uv run ./create_map_poster.py --city "Stanley Park" --country "Canada" -lat 49.3043 -long -123.1443 --theme forest
Multilingual labels (native script + Google Font)
uv run ./create_map_poster.py --city "Tokyo" --country "Japan" --display-city "東京" --display-country "日本" --font-family "Noto Sans JP" --theme japanese_ink

What Actually Exists

  • No scripts/ directory — the trip/location layer is planned but not started.
  • No data/locations.yaml — no vacation catalogue yet.
  • No output/ folder — only the base posters/ dir, which is empty (gitignored).
  • The base engine (create_map_poster.py) works as a one-off CLI command.
Conclusion: The tool works as a one-off CLI command today. The vacation-poster batch workflow (AGENTS.md) is a good next-session goal if poster generation becomes a regular activity — otherwise the single command below is all you need.

Gotchas

Requires internet: Nominatim (geocoding) and OSMnx (road data) both hit the network on every run. No offline mode.
Large dist = slow: --distance 20000 fetches a lot of OSM data. Use 150 DPI instead of 300 for quick previews.
Ambiguous cities: Small towns or landmarks may not geocode correctly. Use -lat/-long to override the centre point.
Posters aren't committed: posters/ is gitignored — regenerate from the command when needed.
Nominatim rate limits: Running --all-themes across multiple cities in a loop can trip rate-limiting — add delays.
